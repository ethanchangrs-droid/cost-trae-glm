## 用户需求概述

用户要求开发一个具有LLM能力加持的费用报销系统，实现三个核心功能：
1. 表单填写和提交
2. 提交时调用规则验证
3. 自然语言规则配置（先实现差旅标准规则）

### 关键需求细节
- **目标用户**: 企业内部员工（10人并发）
- **用户角色**: 普通员工、管理员（无需财务审核）
- **LLM集成**: 阿里云百炼平台的QWEN、DeepSeek等模型
- **费用类型**: 主要针对差旅费用
- **审批流程**: 无需审批，提交时通过规则即成功，不通过即失败
- **部署环境**: 本地电脑运行

### 业务规则示例
- **住宿标准**: 普通员工一线城市≤400元/晚，二线城市≤300元/晚；经理一线城市≤600元/晚，二线城市≤400元/晚；高层实报实销
- **交通工具**: 高层不限座席，经理及普通员工仅限高铁二等座及以下、飞机经济舱
- **补贴标准**: 高层无补贴，经理及普通员工每天补贴100元

## 技术方案总结

### 推荐技术栈
**前端**:
- React 18.x + Ant Design 5.x
- Vite构建工具
- React Router 6.x
- Axios HTTP客户端

**后端**:
- Node.js 18.x + Express.js
- SQLite3 + Sequelize ORM
- JWT身份验证
- Winston日志

**LLM集成**:
- 阿里云百炼平台
- QWEN/DeepSeek模型
- 官方SDK集成

### 核心设计亮点

#### 1. 混合智能表单设计
- **智能提示**: 根据用户输入提供相关建议
- **自动填充**: 基于历史数据和常用信息自动填充
- **混合模式**: 结构化字段填写 + LLM生成的描述信息
- **实时验证**: 表单填写过程中实时验证规则合规性

#### 2. 混合规则配置系统
- **灵活配置**: 支持结构化、自然语言、混合三种规则类型
- **复杂度分析**: LLM自动分析规则复杂度并推荐存储方式
- **智能解析**: 根据规则类型执行不同的解析策略
- **规则管理**: 完整的规则增删改查和版本管理

#### 3. 分层规则验证引擎
- **混合验证**: 支持结构化规则、自然语言规则、混合规则的分层验证
- **策略优化**: 根据规则类型选择最优验证策略
- **详细反馈**: 提供具体的验证结果和修改建议
- **性能监控**: 记录验证执行时间和LLM调用次数

### 数据库设计
设计了6个核心数据表：
- `users`: 用户信息表
- `expenses`: 费用报销主表
- `expense_items`: 费用明细表
- `rules`: 报销规则表（扩展支持混合规则）
- `city_tiers`: 城市等级表
- `rule_validations`: 规则验证记录表（新增）

**混合规则支持**：
- `rules`表增加`rule_storage_type`、`complexity_score`、`structured_content`、`natural_content`字段
- `rule_validations`表记录验证过程、执行时间、LLM调用次数等性能数据

### API设计
设计了完整的RESTful API：
- 认证相关：登录、注册
- 费用管理：创建、查询、验证
- 规则管理：配置、解析、管理、复杂度分析
- 混合规则验证：分层验证、性能监控
- LLM服务：智能提示、自动填充、复杂度分析、混合规则解析
