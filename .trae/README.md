# .trae 开发规范目录

项目的开发规范和配置文件集合，确保团队开发的一致性和代码质量。

## 目录结构

```
.trae/
├── rules/                           # 开发规范文件
│   ├── project_management.md       # 项目管理流程规范
│   ├── coding_standards.md         # 代码编写规范
│   ├── git_standards.md            # Git使用规范
│   ├── testing_standards.md         # 测试规范
│   ├── bug_fix_standards.md         # Bug修复规范
│   └── quick_reference.md           # 快速参考指南
└── README.md                        # 本文档
```

## 规范文件说明

### 1. 项目管理流程规范 (`project_management.md`)
**适用场景**: 项目管理和开发流程

**主要内容**:
- 开发项目初始化流程
- 增量开发前准备
- 增量开发会话规范
- 会话结束流程
- 代码状态要求
- 文件使用规范
- 项目进度管理
- 质量保证

**核心要点**:
- 每次会话只实现一个功能
- 功能完成后必须进行端到端测试
- 使用feature_list.json管理任务
- 使用claude-progress.txt记录进度

### 2. 代码编写规范 (`coding_standards.md`)
**适用场景**: 所有代码编写任务

**主要内容**:
- 开发原则
- 代码规范
- API集成规范
- 组件开发规范
- 数据处理规范

**核心要点**:
- 遵循现有代码风格
- 使用项目已有库和工具
- 注重代码可读性和维护性
- 遵循安全最佳实践

### 3. Git使用规范 (`git_standards.md`)
**适用场景**: 所有Git提交操作

**主要内容**:
- Commit格式规范
- 分支管理策略
- 工作流程规范
- 代码审查要求

**核心要点**:
- 使用约定式提交格式
- 功能分支开发
- 定期合并主分支
- 提交前代码检查

### 4. 测试规范 (`testing_standards.md`)
**适用场景**: 所有测试任务

**主要内容**:
- 前端测试方法
- 后端测试方法
- 测试流程规范
- 测试覆盖率要求

**核心要点**:
- 单元测试覆盖核心逻辑
- 集成测试验证接口
- E2E测试验证用户流程
- 测试驱动开发

### 5. Bug修复规范 (`bug_fix_standards.md`)
**适用场景**: Bug分析和修复

**主要内容**:
- Bug分析流程
- 修复实施规范
- 回退机制
- 预防措施

**核心要点**:
- 先分析再修复
- 最小化修改范围
- 添加回归测试
- 记录修复过程

### 6. 快速参考指南 (`quick_reference.md`)
**适用场景**: 快速查阅规范要点

**主要内容**:
- 文件职责快速参考
- 开发规范文件对应关系
- 文档结构速查
- 记住口诀

**核心要点**:
- 📋 查任务 → feature_list.json
- 📝 查进度 → claude-progress.txt
- 📖 查需求 → PRD/SPEC/UI

## 使用指南

### 开发前准备
1. 阅读 `project_management.md` 了解开发流程
2. 阅读 `coding_standards.md` 了解代码规范
3. 检查 `feature_list.json` 了解当前任务
4. 查看 `claude-progress.txt` 了解项目进度

### 开发过程中
1. 遵循 `coding_standards.md` 编写代码
2. 使用 `git_standards.md` 规范提交
3. 按照 `testing_standards.md` 进行测试
4. 遇到Bug时参考 `bug_fix_standards.md`

### 快速查阅
- 需要快速了解规范时查看 `quick_reference.md`
- 不确定具体规范时查阅对应规范文件
- 需要了解文件职责时查看快速参考

## 规范执行

### 强制执行
- 所有开发任务必须遵守相应规范
- 代码审查时检查规范遵循情况
- 持续集成中包含规范检查

### 规范更新
- 规范需要更新时创建新版本
- 重大变更需要团队讨论
- 更新后通知所有开发人员

### 违规处理
- 发现违规时及时指出
- 严重违规需要重新提交
- 记录违规情况用于改进

## 培训和支持

### 新人培训
- 学习所有规范文件
- 跟随有经验人员实践
- 定期检查规范遵循情况

### 问题支持
- 规范理解问题咨询项目负责人
- 规范改进建议提交Issue
- 规范冲突时优先遵循项目管理规范
