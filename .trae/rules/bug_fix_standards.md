# Bug 修复规范

## 修复前准备
修复 bug 前，必须按照如下步骤：
1. **复现并定位问题**：分析 bug 现象和产生原因
2. **查阅历史记录**：检查工作日志中是否出现过类似现象和原因的问题，及其解决方法
3. **影响范围评估**：检查影响范围，确认是否会影响其他功能
4. **修复方案确认**：必须先提出修复思路和方法，等待确认后才能开始修复

## 修复原则
- **向后兼容**：保持向后兼容，同步修改前后端
- **注释说明**：修复 bug 时，必须先在代码中添加注释，说明 bug 原因和修复方法
- **彻底测试**：修复完成后，必须进行端到端测试，确认 bug 已修复

## 修复流程
1. **问题分析**
   - 详细记录 bug 现象
   - 分析根本原因
   - 确定修复范围

2. **方案设计**
   - 提出修复方案
   - 评估风险和影响
   - 获得确认后实施

3. **代码修复**
   - 添加详细注释说明
   - 实施修复代码
   - 确保代码质量

4. **测试验证**
   - 进行端到端测试
   - 验证修复效果
   - 确保无新问题

5. **文档更新**
   - 更新相关文档
   - 记录修复过程
   - 提交代码变更

## 快速回退机制
如果修改破坏了功能，立即回退：

```bash
# 查看最近的提交
git log --oneline -10

# 回退到指定提交
git revert <commit-hash>
git commit -m "revert: 回退破坏性API修改"

# 紧急情况下使用硬重置（谨慎使用）
git reset --hard <commit-hash>
git push --force-with-lease
```
