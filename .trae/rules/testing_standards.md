# 测试规范

## 测试原则
- 所有功能开发完成后必须进行端到端测试
- 测试应覆盖正常流程、边界情况和异常处理
- 测试失败时，优先修复问题再继续开发；注意遵守bug修复规范

## 前端测试规范

### 端到端测试
- 使用浏览器自动化工具进行端到端测试
- 使用 `browser_snapshot` 验证页面渲染效果
- 使用 `browser_click` 测试用户交互行为
- 测试覆盖主要用户流程和关键功能点

### 前端测试检查项
- 页面加载和渲染是否正常
- 用户交互（点击、输入、导航）是否响应正确
- 数据展示是否准确
- 表单验证和提交是否正常
- 响应式设计在不同设备上的表现
- 用户管理功能（增删改查）是否正常
- 用户选择弹窗组件是否正常工作

## 后端测试规范

### API 测试
- 使用终端命令（curl）或测试脚本验证 API
- 测试所有端点的请求和响应
- 验证数据格式、状态码和错误处理
- 测试 API 的性能和安全性

### 后端测试检查项
- API 端点是否正常响应
- 数据库操作是否正确
- 错误处理和日志记录是否完善
- 数据验证和业务逻辑是否正确
- 用户管理API（增删改查）是否正常
- 按姓名搜索用户功能是否正常

## 无认证系统测试
- 系统无需身份验证，直接访问功能
- 无需测试登录注册流程
- 无需测试JWT中间件
- 所有用户权限相同，无需权限测试

## 测试流程
1. **开发完成后**：进行本地自测
2. **功能测试**：按照需求文档逐项验证
3. **集成测试**：测试前后端协作
4. **回归测试**：确保新功能不影响现有功能
5. **验收测试**：确认满足用户需求

## 测试记录
- 记录测试用例和测试结果
- 发现问题及时记录并跟踪修复
- 测试通过后方可标记功能完成
