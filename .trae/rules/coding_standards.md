# 代码编写规范

## 开发原则
- DRY原则：不要重复代码，抽取公共逻辑
- KISS原则：保持简单，避免过度设计
- 单一职责：每个模块/函数只做一件事
- 代码可读性：写人能读懂的代码，必要时添加注释

## 技术栈规范

### 前端技术栈
- **框架**: React 18.x
- **状态管理**: React Context + useReducer
- **UI组件库**: Ant Design 5.x
- **路由**: React Router 6.x
- **HTTP客户端**: Axios

### 后端技术栈

- **数据库**: SQLite3
- **ORM**: Sequelize
- **日志**: Winston

### LLM集成
- **服务提供商**: 阿里云百炼平台

## 代码规范

### 注释规范
- 使用标准注释标记：TODO（待完成）、FIXME（需修复）、HACK（临时方案）、NOTE（重要说明）
- 注释解释"为什么"，而不是"是什么"

### 避免魔法数字
- 常量使用大写命名（UPPER_SNAKE_CASE），如 MAX_RETRIES = 3
- 禁止在代码中直接使用未命名的数字或字符串

## 外部 API 集成规范
- 调用外部 API 前必须查阅官方文档，确认端点、字段名、参数类型
- 外部 API 返回值必须先验证类型再使用，不要假设返回值结构
- 在代码注释中引用 API 文档链接

## 开发依据
- 代码实现必须符合 PRD 中的功能需求描述
- 技术实现必须遵循 SPEC 中的架构设计和接口定义
- 前端实现必须符合 UI 设计文档的视觉和交互规范
- 如需偏离文档，必须在代码注释中说明原因

## 文档与代码一致性
- 代码实现与文档冲突时，以文档为准
- 如文档有误，先更新文档再修改代码
- 保持文档与代码同步更新
