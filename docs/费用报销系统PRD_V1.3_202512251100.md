# 费用报销系统产品需求文档 (PRD)
**版本**: V1.3  
**创建日期**: 2025年12月24日  
**最后更新**: 2025年12月25日  
**更新内容**: 移除用户登录注册功能，增加用户管理功能，调整用户信息选择方式  

## 1. 项目概述

### 1.1 项目背景
本项目是一个实验性质的LLM能力加持的费用报销系统，旨在通过人工智能技术简化企业差旅费用报销流程，提高用户体验和报销效率。

### 1.2 项目目标
- 实现智能化的差旅费用报销表单填写和提交
- 提供自然语言规则配置功能，降低规则维护成本
- 通过LLM实现智能提示和自动填充功能
- 建立自动化的费用规则验证机制
- 提供便捷的用户信息管理功能

### 1.3 项目范围
- 核心功能：表单填写提交、规则配置、规则验证、用户管理
- 用户群体：企业内部员工（10人并发）
- 部署环境：本地电脑运行
- 重要变更：移除用户登录注册，采用用户信息预置和弹窗选择模式

## 2. 用户角色与权限

### 2.1 系统用户
- 所有用户拥有相同的系统访问权限
- 无需登录即可访问系统功能
- 通过用户管理功能预置用户信息

### 2.2 用户管理功能
- 管理员可进行用户信息的增删改查操作
- 用户信息包含：姓名、工号、级别
- 支持按姓名搜索用户功能

## 3. 功能需求

### 3.1 用户管理功能

#### 3.1.1 用户信息管理
- **用户列表查看**：以表格形式展示所有用户信息
- **用户添加**：支持新增用户，包含姓名、工号、级别信息
- **用户编辑**：支持修改现有用户信息
- **用户删除**：支持删除不需要的用户信息
- **用户搜索**：支持按姓名搜索用户

#### 3.1.2 用户信息字段
- **姓名**：用户真实姓名，必填
- **工号**：员工唯一标识，必填且唯一
- **级别**：员工级别（employee/manager/executive），必填

### 3.2 表单填写和提交功能（混合模式）

#### 3.2.1 票据识别与信息提取
- **多模态票据识别**：支持上传各类票据照片，AI自动识别关键信息
- **结构化信息提取**：自动提取票据类型、金额、日期、商家、出发地/目的地等结构化数据
- **智能描述生成**：LLM基于识别结果生成自然语言描述，解释票据内容和合规性建议

#### 3.2.2 混合填单界面
- **票据识别结果区域**：显示上传的票据照片和AI识别状态
- **结构化信息区域**：以表格形式展示自动提取的结构化数据，支持手动编辑
- **智能说明区域**：显示LLM生成的自然语言描述，提供编辑和重新生成功能
- **基础信息补充**：通过弹窗选择用户信息，补充出差时间、事由、关联项目等必要信息

#### 3.2.3 用户信息选择
- **弹窗选择**：填单时涉及用户信息的内容，通过弹窗选择用户
- **姓名搜索**：支持按姓名搜索用户，快速定位
- **信息自动填充**：选择用户后自动填充相关用户信息到表单

#### 3.2.4 LLM智能辅助
- **智能提示**：根据识别内容和输入信息提供相关建议
- **自动填充**：基于票据识别结果自动填充结构化字段
- **合规性建议**：LLM分析票据信息，提供补充建议和风险提示

#### 3.2.5 提交验证
- 实时规则匹配和验证
- 提交前预览和确认
- 验证结果即时反馈

### 3.3 自然语言规则配置功能

#### 3.3.1 规则类型
- **住宿标准规则**：按城市等级和职级设定住宿费用上限
- **交通工具规则**：按职级设定可乘坐的交通工具和座席等级
- **补贴标准规则**：按职级设定每日补贴金额

#### 3.3.2 自然语言配置
- 支持类似"普通员工在一线城市住宿，每晚不超过400元"的自然语言描述
- LLM解析自然语言规则并转换为结构化配置
- 规则冲突检测和提示

#### 3.3.3 规则管理
- 规则的增删改查
- 规则版本管理
- 规则生效时间设置

### 3.4 规则验证功能

#### 3.4.1 实时验证
- 表单填写过程中实时验证
- 违规项目高亮提示
- 提供修改建议

#### 3.4.2 提交验证
- 综合验证所有费用项目
- 生成验证报告
- 通过/失败结果判定

## 4. 非功能需求

### 4.1 性能需求
- 支持10个并发用户
- 表单响应时间 < 2秒
- 规则验证响应时间 < 3秒
- 用户搜索响应时间 < 1秒

### 4.2 可用性需求
- 界面简洁直观，易于操作
- 提供操作指引和帮助文档
- 支持常见浏览器访问
- 无需登录即可使用系统

### 4.3 安全需求
- 本地数据存储安全
- 用户信息管理权限控制（可选）
- 数据传输加密

## 5. 业务规则示例

### 5.1 住宿标准规则
- 普通员工：一线城市≤400元/晚，二线城市≤300元/晚
- 经理：一线城市≤600元/晚，二线城市≤400元/晚  
- 高层：实报实销

### 5.2 交通工具规则
- 高层：不限座席
- 经理及普通员工：高铁二等座及以下、飞机经济舱

### 5.3 补贴标准规则
- 高层：无补贴
- 经理及普通员工：100元/天

## 6. 用户故事

### 6.1 系统用户故事
**作为** 一名系统用户  
**我希望** 能够快速填写差旅费用报销表单  
**以便** 获得智能提示和自动填充，减少填写时间

**作为** 一名出差员工  
**我希望** 系统能够实时验证我的费用是否符合公司规定  
**以便** 及时调整不合规的费用项目

**作为** 一名填单用户  
**我希望** 能够通过弹窗快速选择用户信息  
**以便** 准确关联报销人员信息

### 6.2 管理员用户故事
**作为** 一名管理员  
**我希望** 能够管理用户信息（增删改查）  
**以便** 维护准确的用户数据

**作为** 一名管理员  
**我希望** 能够用自然语言描述报销规则  
**以便** 快速配置和调整费用标准

**作为** 一名管理员  
**我希望** 能够查看所有报销记录和验证结果  
**以便** 监控和分析报销情况

## 7. 验收标准

### 7.1 功能验收
- 用户能够成功填写并提交差旅费用表单
- 管理员能够进行用户信息的增删改查操作
- 用户能够通过弹窗选择用户信息
- 管理员能够通过自然语言配置规则
- 系统能够准确验证费用是否符合规则
- LLM智能辅助功能正常工作

### 7.2 性能验收
- 10个并发用户同时使用时系统响应正常
- 各功能模块响应时间满足需求要求
- 用户搜索功能快速响应

### 7.3 用户体验验收
- 界面操作流畅，用户反馈良好
- 智能提示准确有用
- 错误提示清晰易懂
- 用户选择弹窗操作便捷

## 8. 风险与限制

### 8.1 技术风险
- LLM API调用的稳定性和成本控制
- 自然语言规则解析的准确性
- 本地部署的性能限制

### 8.2 业务风险
- 规则配置不当可能导致验证错误
- 用户信息管理不当可能导致数据混乱
- 用户对自然语言配置的理解偏差

### 8.3 项目限制
- 实验性质，功能相对简化
- 仅支持差旅费用，不包含其他费用类型
- 无审批流程，仅规则验证
- 无用户权限控制，所有用户权限相同
